# STM32H743 FMC16 提速说明

当前已经跑通的是 FMC16 **最小通信测试**，不是完整业务板闭环，也不是最大吞吐验收。

最小测试覆盖：

- STM32H743 与 XO2 的 16-bit 异步读写；
- RESET_NOTICE、LINK_HELLO、DEVICE_INFO 三个启动包；
- `GET_CAPABILITIES`；
- ACK、RESPONSE、NACK 及 CRC 校验；
- 最小链路连续三轮板级通过。

该结果证明基础链路和 wire format 可用，但不代表完整 personality 的 PI、PO、PIO 业务已经上板通过，也不代表下面的提速 profile 已经完成板级验收。

## 2. 当前基线与提速候选

### 2.1 已验证基线

```text
FMC kernel = 100 MHz
BTR1       = 4/6/255/10       读
BWTR1      = 4/6/255/10       写
DATAST     = 255
```

`DATAST=255` 对应约 2.55 μs 数据窗口，是当前最小通信测试的稳定回退配置。

### 2.2 首个提速候选

建议 STM32 侧首先验证：

```text
FMC kernel = 100 MHz
BTR1       = 4/6/40/10        读
BWTR1      = 4/6/40/10        写
DATAST     = 40
```

在 100 MHz FMC kernel 下，`DATAST=40` 约等于 400 ns 数据窗口。按当前单字异步访问模型估算：

- 裸总线速率约 32 Mbit/s，即约 4 MB/s；
- 最大 payload 连续传输的有效速率约 3.5～3.8 MB/s；
- 当前稳定 SPI 25 MHz 约为 3.125 MB/s，因此理论上约快 1.28 倍；
- 以上是时序模型估算，不是板级实测结果。

该 profile 不改变 XO2 RTL、FMC 引脚、MPU、wire format 或协议字段。

## 3. STM32 侧修改范围

### 3.1 FMC 初始化

读写必须同时修改，不能只改读时序：

```c
read_timing.DataSetupTime  = 40U;
write_timing.DataSetupTime = 40U;
```

使用独立测试固件时，寄存器含义保持：

```text
FMC_Bank1_R->BTCR[1]      = BTR1，读时序
FMC_Bank1E_R->BWTR[0]     = BWTR1，写时序
BTCR[2]                   = BCR2，不得当作 BWTR1
```

若使用直接寄存器 profile，`4/6/40/10` 对应的读回值应约为：

```text
BTR1  = 0x001A2864
BWTR1 = 0x001A2864
```

启动日志应打印实际读写 `DATAST=40`，不得继续打印旧的 `DATAST=10` 或 `DATAST=255`。

### 3.2 不需要修改的内容

- XO2 侧物理层 RTL；
- XO2 顶层、LPF 和位流；
- `sys_clk=50 MHz`；
- FMC16 引脚和 AF 配置；
- MPU 的 `0x60000000` 区域配置；
- 包格式、CRC、能力字和命令编号。

## 4. 提速验证顺序

1. 使用当前已验证的 `DATAST=255`，先重复最小测试，确认 XO2 位流、线序和测试环境没有变化。
2. 只修改 STM32 侧读写 `DATAST` 为 40，重新构建、烧录并回读 BTR1/BWTR1。
3. 先验证读方向：三个启动包、长度、序号、CRC16、CRC32 全部正确。
4. 再验证写方向：`GET_CAPABILITIES` 的 ACK/RESPONSE 和未知命令的 NACK 全部正确。
5. 进行连续读写压力测试，读、写分别记录 word/s、裸总线速率和有效 payload 速率。
6. 至少重复三轮；出现 CRC 错误、SOF 丢失、超时、ACK 缺失或 RESPONSE 缺失时，立即恢复 `DATAST=255`，不要继续压缩窗口。

读失败时优先检查 BTR1；写失败时优先检查 BWTR1。两者不能混用。

## 5. 后续提速路线

提速应按单变量顺序进行：

| 阶段 | STM32 profile | 理论裸速 | 状态 |
|---|---|---:|---|
| 当前基线 | `DATAST=255` | 时序估算约 0.75 MB/s | 最小链路已验证，速率未实测 |
| 第一阶段 | `DATAST=40` | 约 4 MB/s | 首个候选，待板测 |
| 第二阶段 | `DATAST=30` | 约 5 MB/s | 通过第一阶段后再测 |
| 第三阶段 | `DATAST=10` | 约 10 MB/s | 激进候选，不能直接采用 |
| 连续 NE1/burst | 需重新定义合同 | 约 12.5 MB/s 以上 | 不属于当前接口合同 |

`DATAST=10` 及连续 NE1/burst 需要重新做读写相位、同步延迟、数据保持、方向切换和板级误码验证。没有这些证据时，接收方应以 `DATAST=255` 为回退配置，或只采用已经实测通过的 profile。

## 6. 交接结论

当前交接的是：

1. **已完成**：最小 FMC16 读写和基础协议闭环；
2. **首个提速方向**：STM32 侧将读写 `DATAST` 从 255 改为 40；
3. **XO2 侧要求**：`DATAST=40` 不需要修改 RTL 或重新定义协议；
4. **验收条件**：读写、CRC、连续包和回退路径均通过后，才可以把 4 MB/s 写成新的 STM32 侧性能基线；
5. **未覆盖**：完整 personality 的业务上板、PI/PO/PIO 逐位验证和更高速 burst 合同。
