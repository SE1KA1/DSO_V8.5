# FMC16 通信代码交接说明

## 交付内容

| 目录 | 内容 |
|---|---|
| `include/` | 通用协议、完整板编解码、STM32H743 端口和测试入口 |
| `src/` | CRC、收发、完整板构包解析、FMC 初始化和字读写 |
| `examples/` | 启动包和 `GET_CAPABILITIES` 闭环测试 |
| `tests/` | 最小链路测试和完整板编解码测试 |
| `docs/FMC16_最小通信协议.md` | 数据包格式、CRC、命令和响应定义 |
| `docs/STM32H743_移植说明.md` | STM32H743 引脚、时钟、MPU 和 FMC 配置 |
| `docs/XO2FMC完整板数据对接.md` | PI、PO、PIO、状态、事件的构包和解析方法 |

## 两部分代码

| 部分 | 文件 | 用途 | 验证状态 |
|---|---|---|---|
| 最小通信 | `fmc16_protocol.*`、`fmc16_minimal_smoke.c` | 建链、能力查询、ACK/RESPONSE/NACK | 已完成最小板三轮实测 |
| 完整板基础 | `fmc16_full_board.*` | PI/PO/PIO、快照、事件、主机状态 | C/ARMCLANG 验证通过，完整板上板待验 |

先跑最小通信。结果为 0 后，再接入完整板接口。不要用完整板接口测试结果替代最小链路验收，也不要把 PC 编解码测试写成完整板已经上板通过。

## 已支持的通信

- 16-bit 异步 FMC 读写；
- `RESET_NOTICE`、`LINK_HELLO`、`DEVICE_INFO` 启动包；
- CRC16/CCITT-FALSE 和 CRC32/MPEG-2；
- `GET_CAPABILITIES` 命令；
- 独立的 ACK 和 RESPONSE；
- 未知命令返回 NACK。

接收端必须支持异步读和异步写，对应能力掩码 `0x00000003`。能力判断采用包含关系，不要求能力字精确等于该值：

```c
(peer_capabilities & 0x00000003UL) == 0x00000003UL
```

最小通信端上报 `0x00000003`，完整 XO2 FMC 端上报 `0x00002BF7`，两者都能通过基础通信测试。额外能力只能在上层代码已经实现相应消息后启用。

## 接入步骤

1. 将 `include/` 加入头文件搜索路径。
2. 将以下文件加入 STM32H743 HAL 工程：

   ```text
   src/fmc16_protocol.c
   src/fmc16_port_stm32h743.c
   examples/fmc16_minimal_smoke.c
   ```

3. 按 `STM32H743_移植说明.md` 配置系统时钟、MPU 和 FMC 引脚。
4. 复位 XO2，使三个启动包重新进入发送队列。
5. 调用并读取对端能力：

   ```c
   #include "fmc16_smoke.h"

   uint32_t peer_capabilities;
   int result = fmc16_minimal_smoke_run_with_capabilities(&peer_capabilities);
   ```

6. `result == 0` 表示基础通信通过。`peer_capabilities` 用于区分最小通信端和完整端。

完整板继续接入时，再加入：

```text
include/fmc16_full_board.h
src/fmc16_full_board.c
```

解析 PI、PO、PIO 和事件的方法见 `XO2FMC完整板数据对接.md`。

## 测试

先在 PC 上运行协议测试：

```text
python tests/test_golden_vectors.py
```

预期输出：

```text
CRC16 GOLDEN: PASS
CRC32 GOLDEN: PASS
GET_CAPABILITIES PACKET: PASS
MINIMAL/FULL CAPABILITIES: PASS
ALL PASS
```

`tests/test_protocol.c` 用于检查 C 实现，包括正确包校验和损坏 CRC 拒绝。

`tests/test_full_board.c` 单独检查完整板的构包、解析、字段位置、保留位和只读权限。该测试不访问硬件。

使用支持 C11 的编译器运行：

```text
gcc -std=c11 -Wall -Wextra -Werror -I include src/fmc16_protocol.c tests/test_protocol.c -o test_protocol
gcc -std=c11 -Wall -Wextra -Werror -I include src/fmc16_protocol.c src/fmc16_full_board.c tests/test_full_board.c -o test_full_board
```

两个程序的预期结果分别是：

```text
FMC16 C PROTOCOL TEST: ALL PASS
FMC16 FULL BOARD CODEC TEST: ALL PASS
```

## 上板检查顺序

1. 空读返回 `0xFFFF`。
2. 依次收到 RESET_NOTICE、LINK_HELLO、DEVICE_INFO。
3. 三个包的长度、序号和两级 CRC 均正确。
4. 发送 GET_CAPABILITIES。
5. 收到同一 transaction ID 的 ACK。
6. 收到同一 transaction ID 的 RESPONSE，能力字与 LINK_HELLO 一致，并且包含 `0x00000003`。
7. 发送未知 opcode，收到 NACK/BAD_OPCODE。
8. 复位 XO2 后重复三轮。

## 常见问题

| 现象 | 检查项 |
|---|---|
| 一直读到 `0xFFFF` | XO2 是否运行、JTAG 是否断开、NE1/NOE 是否接通 |
| 能找到 SOF，但 CRC 错 | D0-D15 位序、DATAST、32-bit 高低字顺序 |
| 启动包正常，没有 ACK | NWE、BWTR1 写时序、命令长度和 CRC |
| ACK 正常，没有 RESPONSE | transaction ID、响应包解析和 XO2 发送队列 |
| 最小端通过，完整端失败 | 是否错误地把能力字写成必须等于 `0x00000003` |
