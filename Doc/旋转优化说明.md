# 旋转优化说明

## 当前架构（逻辑横屏 + 软件旋转）

- **emWin**：逻辑 800×480 横屏，绘制到 `VRAM_LOGICAL_ADDR`
- **LTDC**：物理 480×800 竖屏，扫描 `VRAM_PHYSICAL_0/1`
- **每帧**：`ManualRotateToPhysical` 用 CPU 做 90° 旋转，约 38 万像素

## 已做短期优化

- 旋转块从 16×16 改为 **32×32**，减少循环次数，更好利用 L1 Cache
- 已使用 `__restrict` 指针

## “1.5 倍屏”可能原因

物理竖屏直接显示异常，常见原因：

1. **LTDC 分辨率与面板不一致**  
   LTDC 配置为 800×480，而面板为 480×800，会导致拉伸或错位。

2. **Stride 错误**  
   emWin 若按 800 像素/行写缓冲，而 LTDC 按 480 像素/行扫描，会出现错行或 1.5 倍效果。

3. **坐标/尺寸未交换**  
   使用 ROTATION_CW 时需 `LCD_GetSwapXY()` 并正确设置 `LCD_SetSizeEx(0, 480, 800)`。

## 坐标映射方案（中期，改动较大）

目标：emWin 直接写入物理竖屏缓冲，省去整块旋转。

### 方案 A：emWin 内置 ROTATION_CW

1. 将 `ORIENTATION_0` 改为 `ROTATION_CW`，使用 `GUIDRV_LIN_OSX_16`
2. 将 `_aAddr` 指向物理缓冲（如 `VRAM_PHYSICAL_0`）
3. 在 `LCD_X_Config` 中按 `LCD_GetSwapXYEx(0)` 设置尺寸：
   ```c
   if (LCD_GetSwapXYEx(0)) {
       LCD_SetSizeEx(0, 480, 800);   /* 物理尺寸 */
       LCD_SetVSizeEx(0, 480, 800);
   } else {
       LCD_SetSizeEx(0, 800, 480);
       LCD_SetVSizeEx(0, 800, 480);
   }
   ```
4. **双缓冲**：需在 VSYNC 时切换 emWin 的 VRAM 地址，或使用 emWin 多缓冲机制

**风险**：STemWin 的 OSX 驱动实现可能与预期不同，需实测。

### 方案 B：自定义驱动做坐标映射

在 `_LCD_SetPixelIndex` 等底层函数中做变换：

- 逻辑 `(x, y)` → 物理 `(479 - y, x)`
- 物理地址：`base + (x * 480 + (479 - y)) * 2`

需重写 SetPixel、FillRect、DrawLine、DrawBitmap 等，工作量较大。

### 方案 C：保持现状 + 继续优化

- 当前 32×32 块已能减少部分 CPU 负载
- 若帧率足够，可暂不改为坐标映射
- 后续可尝试 DMA2D 2D 拷贝（需确认 H7 DMA2D 是否支持 stride 变换）

## 建议

1. 先验证 32×32 块旋转的实际性能
2. 若需进一步优化，再尝试方案 A，并准备回退到当前逻辑横屏 + 旋转
3. 方案 B 仅在方案 A 不可行时考虑
